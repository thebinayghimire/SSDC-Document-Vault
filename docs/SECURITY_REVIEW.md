# Security review - 7 October 2026

**Release recommendation: blocked for production.** Local synthetic development
is usable. Remaining high-severity image advisories, approved hosting/policies,
and independent review must be resolved before real SSDC records or public release.
This is the implementation agent's automated self-review, not an independent
penetration test and not organizational approval.

## Scope and methodology

Reviewed custom identity, password/TOTP/recovery flows, session middleware,
role changes, admin assurance, folder inheritance/document overrides, upload and
scan lifecycle, private storage, all document routes, PDF.js configuration,
caching/browser policies, operator commands and paired encrypted backups.
Used PostgreSQL adversarial tests, Playwright browsers, real ClamAV INSTREAM/EICAR,
local production Compose with TLS, dependency scans and Docker Scout image scans.
Only synthetic fixtures were used. No public host, actual staff devices or
confidential records were tested.

## Access-path inventory

| Path | Methods | Enforcement |
|---|---|---|
| `/`, `/folders/<id>/` | GET/HEAD | Current folder grants; permission-filtered document query before pagination/search |
| `/documents/<id>/` | GET/HEAD | Current document ACL; ready/unarchived/undeleted version only |
| `/documents/<id>/content/` | GET/HEAD, including ranges | Same ACL independently on every request; bounded single ranges; no-store |
| `/documents/<id>/thumbnail/` | GET/HEAD | Same ACL; safe generated raster only |
| Folder upload / document replacement | GET/POST | Manager role plus scope/document manage grant, recent identity, CSRF, rate/quota limits |
| Document metadata/lifecycle/version restore | GET/POST or POST | Current manage policy, destination grants, version ownership, recent identity, CSRF |
| Folder creation | GET/POST | Managed parent; root requires admin; inherited children only for managers |
| `/admin/*` | Admin-supported methods | Administrator, verified MFA, recent authentication; model actions audited |
| Login/MFA | GET/POST | Generic credentials/errors, CSRF, DB-backed rate limits; password before enrollment/challenge |
| Logout / password change | POST / GET+POST | Session, CSRF, supported hashing and revocation |
| `/health/` | GET/HEAD | Minimal availability response; no infrastructure details |

No media/public original-file route, export, persistent signed URL, office converter,
or service-worker document cache exists. Historical versions have no arbitrary
delivery endpoint; restoring them requires current document manage rights.

## Confirmed defects fixed during development

| Finding | Fix and evidence |
|---|---|
| Invalid development MFA key | Correct development key; Fernet startup validation; enrollment/challenge/replay/recovery tests |
| Proxy stripped nonstandard port, failing legitimate CSRF origin checks | Forward original Host header; actual browser login and HTTPS smoke passed |
| Mobile table hidden label caused page overflow | Position table container; 390px browser layout assertion passed |
| Small images could omit preview bytes from quota accounting | Reserve preview bytes under global quota lock; account actual generated bytes after publication; quota regression test |
| Document-only manager grant could not update title in current folder | Allow retaining current folder while requiring destination manage grants for moves; positive/negative regression tests |
| Excessive folder creation | Configurable 1,000-folder cap, depth guard and scoped rate limit; cap regression test |
| Accidental static/private storage overlap | Reject overlapping configuration at startup; regression test |

Scope limitation: the "last administrator" guard protects ordinary admin changes
and serializes saves. Host operators can still bypass it through direct DB writes.

## Container advisories and release blockers

Docker Scout results on Linux/amd64, critical/high severities only:

| Image | Initial critical/high | After remediation critical/high |
|---|---|---|
| App | 0 / 14 | 0 / 2 |
| PostgreSQL | 2 / 30 | 0 / 4 |
| Nginx | 0 / 4 | 0 / 0 |
| ClamAV | 0 / 2 | 0 / 1 |

Remediations: use pinned Python/PostgreSQL Debian 13 bases with patched OpenSSL;
remove pip and its unnecessary vendored packages from the app runtime; remove
unused proxy modules and upgrade available Alpine security packages; upgrade
scanner dependencies; run PostgreSQL as postgres without its old root-only gosu
helper. The prepared DB filesystem is copied into the final image so obsolete
helper bytes do not remain in inherited layers or its SBOM. Final scan confirms
the old Go-helper advisories are absent. Reindexed/refreshed collation versions
on the local synthetic databases after the Debian upgrade.

Unresolved advisories (package presence/scan findings, not demonstrated endpoint exploits):

| Severity | Advisory | Affected release images |
|---|---|---|
| High | CVE-2026-95619 | App, PostgreSQL: gcc-14 source package runtime libraries |
| High | CVE-2026-85091 | App, PostgreSQL: zlib |
| High | CVE-2026-74860 | PostgreSQL: libxml2 |
| High | CVE-2026-86140 | PostgreSQL, ClamAV: libxml2 |

These are four distinct advisories repeated across images, seven high-severity scan
entries in total. Available selected distribution packages did not clear these
findings. Do not treat source-package matches as proof of application exploitability,
or assume they are harmless. Obtain supported patched images or a qualified,
documented component/reachability assessment before release. No exception is
silently suppressed and no production risk acceptance has been granted.

The 7 October refresh no longer reported CVE-2026-102010 against the unchanged
GCC runtime package; this is a changed scan result, not proof of a package fix.
Refreshed proxy/scanner builds installed Alpine zlib 1.3.2-r1, clearing the newly
reported zlib finding there. Always refresh build steps and scans before release.

Reproduce: build all services with Compose, then run
`docker scout cves --only-severity critical,high --exit-code local://<image>` for
`ssdc-vault-app`, `ssdc-postgres`, `ssdc-proxy`, and `ssdc-clamav`.
Reports are in ignored `artifacts/app-scan-final.txt`,
`ssdc-postgres-scan-final.txt`, `ssdc-proxy-scan-final.txt`, and `ssdc-clamav-scan-final.txt`.
Scout also reported Windows temporary-file cleanup locks; reports were still
written and inspected. Scan finding counts were not replaced with success claims.

## Verification evidence and limitations

PostgreSQL backend suite, Linux-container regression run, browser checks, HTTPS
cookie/header smoke, ClamAV clean/EICAR checks, dependency checks, migration/lint
checks and encrypted backup/temporary-DB restore were actually executed. Exact
final counts are maintained in `PROGRESS.md`; XML/screenshots are in `artifacts/`.
Production deployment checks report only `security.W021` because HSTS preload
registration is deliberately pending domain ownership decisions; it is not hidden.

Residual risks: authorized byte extraction/screenshots/OCR; admin/host compromise;
parser or antivirus zero-days; DB-operator audit tampering; captured content after
revocation; single-host downtime; browser accessibility of canvas-only PDFs.
Parser subprocesses have time/resource limits and no inherited credential
environment, but share the app UID/filesystem. They are not an independent
container trust boundary. Global folder-policy resolution is bounded by the
configured folder limit but has not undergone representative office load testing.

Still required: supported-image advisory closure/assessment, independent security
review, approved host/domain/certificate renewal, staff permission assignments,
retention and recovery policy, encrypted offsite backups/key custody, monitoring
alert destination, capacity/accessibility checks on actual staff devices, and
formal SSDC release/risk decisions. No real organizational data has been uploaded.
